## День 1 — Требования из `Coursework.pdf`

### 1. Что является ядром работы
- Основной deliverable — экспериментальная оценка границ применимости современных VLM для извлечения физических характеристик объектов на статических 2D-изображениях.
- Теоретическая часть нужна как рамка для экспериментальных результатов, а не как самостоятельный центр работы.
- Важна воспроизводимость: единый пайплайн, фиксированный протокол, единый формат ответов и одинаковые метрики для всех моделей.

### 2. Что обязательно должно быть в экспериментальном протоколе
- Zero-shot инференс.
- Few-shot инференс.
- Сравнение нескольких компактных VLM, пригодных для запуска на одном GPU уровня A100.
- Анализ влияния сегментации.
- Анализ границ применимости и типичных ошибок.

### 3. Обязательная объектно-ориентированная постановка
- Единица анализа — объект на изображении, а не сцена целиком.
- Для объекта должна быть задана локализация.
- При наличии маски нужно уметь использовать её в отдельных режимах подачи визуального входа.

### 4. Набор свойств из PDF, который логично считать основным протоколом этапа 1
- `material`
- `transparency`
- `reflectance`
- `surface_roughness`
- `rigidity`
- `fragility`
- `wetness`
- `state`
- `weight_hint`
- `temperature_hint`
- `phase`
- `filled_state`
- `slipperiness_hint`

### 5. Что критично для разметки и ответа модели
- Для каждого свойства допускается значение `unknown`.
- `unknown` — не ошибка, а часть постановки и явная модель границ применимости.
- Модель должна возвращать значения строго из заданных словарей.
- Формат ответа должен быть JSON.

### 6. Режимы визуального входа, которые прямо зафиксированы в PDF
- `Raw` — crop объекта по bbox.
- `Mask-overlay` — crop объекта с наложением контура/маски.
- `Masked-object` — объект, вырезанный по маске на нейтральном фоне.

### 7. Метрики, которые нужно иметь в коде и в отчёте
- `Accuracy`
- `Macro-F1`
- `Coverage`
- `Selective Accuracy`

### 8. Экспериментальные гипотезы, которые уже следуют из PDF
- Segmentation может снижать неоднозначность и улучшать извлечение свойств.
- Few-shot может улучшать качество по части свойств по сравнению с zero-shot.
- Есть класс свойств, для которых одиночного 2D-изображения принципиально недостаточно, и корректным ответом остаётся `unknown`.
- Joint-prompt и per-property prompting нужно рассматривать как инженерную и исследовательскую абляцию, потому что от них зависят стабильность JSON и качество извлечения.

### 9. Что в PDF выглядит как обязательный минимум для сильного результата
- Стабильный единый пайплайн.
- Несколько моделей в одинаковом протоколе.
- Zero-shot + few-shot.
- Анализ влияния сегментации.
- Метрики по каждому свойству.
- Интерпретация ограничений постановки, а не только чисел.

### 10. Что можно считать расширением, а не ядром этапа 1
- Полноценное дообучение нескольких моделей.
- Очень широкая ontology физических свойств сверх компактного словаря из PDF.
- Масштабная ручная разметка нового датасета с нуля.

## Вывод Дня 1
- Для сильного результата этапа 1 лучше зафиксировать основной экспериментальный протокол на компактном словаре из PDF.
- Текущий `abo_150_expanded` и существующий пайплайн можно использовать как инженерную основу и как источник дополнительных экспериментов.
- Главный риск проекта — расползание в слишком широкую постановку раньше, чем будут получены первые воспроизводимые baseline-результаты.
